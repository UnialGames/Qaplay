# 시트 연동

기획자와 QA가 쓰는 TC 시트와 qaplay를 잇는 방법이다. 시트에는 "무엇을 확인할지"가 있고, 규칙 파일에는 "어떻게 확인할지"가 있다. 둘은 TC 번호로 이어진다.

- 상태: CSV 파일과 Excel 파일(xlsx)을 지원한다. Google Sheets는 같은 방식으로 더하는 중이다
- 실행해 볼 수 있는 예: 저장소의 `samples/sheet/`(CSV: TC 표 `tc.csv`와 설정 `qaplay-sheet.json`), `samples/sheet-xlsx/`(Excel: 통합 문서 `qa.xlsx`와 설정)

## 1. 흐름

1. 사람이 시트에 TC 한 줄을 적는다(무엇을 확인할지)
2. 규칙을 쓰는 쪽(AI나 프로그래머)이 `qaplay tc show TC-012`로 그 줄을 읽는다
3. 규칙 파일을 쓰고 머리말에 `tc: TC-012`를 적는다([규칙 파일 명세](rules.md) 2절)
4. `qaplay run 규칙들`을 실행하면 러너가 그 TC의 줄에 결과를 적고, 요약 표에 한 줄을 더한다

같은 내용을 양쪽에 두지 않는다. 시트에는 실행 방법을 적지 않고, 규칙 파일에는 TC의 설명을 옮겨 적지 않는다.

## 2. 표 두 개

TC 표: TC 한 줄에 최신 결과만 있다. 실행할 때마다 줄이 늘지 않는다.

| 칸 | 누가 적나 | 내용 |
|---|---|---|
| TC 번호 | 사람 | 규칙 파일의 `tc`와 같은 글자 |
| 내용, 기대 결과 | 사람 | 무엇을 하고 무엇을 확인하는지. 이 둘이 바뀌면 규칙을 다시 봐야 한다(4절) |
| 그 밖의 칸(화면, 사전 조건, 우선순위, 담당 등) | 사람 | 도구는 읽기만 한다. 팀이 쓰던 칸을 그대로 둔다 |
| 규칙 상태 | 도구 | 있음 / 없음 / 갱신 필요 |
| 최신 결과 | 도구 | 통과 / 실패 / 불안정. 한 번도 돌리지 않았으면 비어 있다 |
| 최신 실행 | 도구 | 빌드 / 기기 / 일시 |
| 버그 리포트 | 도구 | 그 TC의 실패가 버그 리포트로 올라갔으면 그 번호(`BUG-0003`) |
| 리포트 | 도구 | 실행 리포트의 위치(만드는 중) |
| 규칙 기준 | 도구 | 규칙을 쓸 때의 내용과 기대 결과를 줄인 값. 사람이 볼 필요는 없다 |

- 도구는 자기 칸만 고친다. 사람이 적은 칸은 건드리지 않는다.
- 도구의 칸이 시트에 없으면 맨 뒤에 더한다. 미리 원하는 자리에 그 이름의 칸을 만들어 두면 거기에 적는다.
- 같은 TC를 실행하는 규칙이 여럿이면 하나라도 실패하면 실패다.
- 이번에 실행하지 않은 TC의 결과는 그대로 둔다.
- 불안정은 처음에는 실패했다가 다시 돌려 통과한 것이다.

요약 표: 실행할 때마다 한 줄이 는다.

| 칸 | 내용 |
|---|---|
| 빌드, 실행 일시, 기기 | 무엇을 언제 어디서 돌렸는지 |
| 전체, 통과, 실패, 불안정 | 이번에 실행한 규칙의 수 |
| 통과율 | (통과 + 불안정) / 전체 |

## 3. 설정 파일

시트가 어디에 있고 칸 이름이 무엇인지를 `qaplay-sheet.json`에 적는다. 러너를 실행한 폴더에 이 파일이 있으면 따로 말하지 않아도 쓰고, 다른 곳에 있으면 `--sheet 파일`로 알려 준다. 안의 경로는 이 파일이 있는 폴더 기준이다.

```json
{
  "type": "csv",
  "tc": "tc.csv",
  "summary": "summary.csv",
  "rules": ["../../unity/Assets/Sample/Rules"],
  "columns": { "tc": "TC 번호", "content": "내용", "expected": "기대 결과", "rule": "규칙 상태", "result": "최신 결과" },
  "labels": { "passed": "통과", "failed": "실패", "flaky": "불안정", "notRun": "미실행", "ruleOk": "있음", "ruleMissing": "없음", "ruleOutdated": "갱신 필요" }
}
```

| 항목 | 뜻 |
|---|---|
| `type` | 시트의 종류. `csv`(기본)나 `xlsx` |
| `file` | `xlsx`일 때만: 통합 문서 파일 |
| `tc` | TC 표. `csv`에서는 파일, `xlsx`에서는 탭 이름 |
| `summary` | 요약 표. `csv`에서는 파일, `xlsx`에서는 탭 이름. 적지 않으면 요약을 남기지 않는다. 없으면 만든다 |
| `rules` | 규칙 파일이 있는 폴더들. 규칙 상태(있음, 없음)는 여기에서 `tc`가 적힌 규칙을 찾아 정한다 |
| `columns` | 칸 이름. 팀이 쓰던 시트의 이름에 맞춘다. 적지 않은 것은 아래의 기본 이름이다 |
| `labels` | 칸에 적는 말. 적지 않은 것은 아래의 기본 말이다 |

`columns`에 쓸 수 있는 이름과 기본값

| 이름 | 기본 칸 이름 | 표 |
|---|---|---|
| `tc`, `content`, `expected` | `TC`, `Steps`, `Expected` | TC 표, 사람이 적는 칸 |
| `rule`, `result`, `run`, `bugs`, `report`, `basis` | `Rule`, `Result`, `Last run`, `Bugs`, `Report`, `Rule basis` | TC 표, 도구가 채우는 칸 |
| `build`, `time`, `device`, `total`, `passed`, `failed`, `flaky`, `rate` | `Build`, `Time`, `Device`, `Total`, `Passed`, `Failed`, `Flaky`, `Pass rate` | 요약 표 |

`labels`에 쓸 수 있는 이름과 기본값: `passed`, `failed`, `flaky`, `notRun`(`not run`), `ruleOk`(`ok`), `ruleMissing`(`missing`), `ruleOutdated`(`outdated`)

- 모르는 이름을 적으면 실행하지 않고 알린다. 오타 난 설정이 조용히 무시되지 않는다.
- CSV 파일은 UTF-8이다. 쓸 때는 Excel이 한글을 제대로 읽도록 BOM을 붙인다.
- Excel로 열어 둔 파일(CSV, xlsx)에는 쓸 수 없다. 그때 러너는 결과를 적지 못했다고 알리고, 테스트의 종료 코드는 그대로 둔다. 읽기(`tc list`, `tc show`)는 열어 둔 채로도 된다.

Excel 파일(xlsx)일 때

```json
{ "type": "xlsx", "file": "qa.xlsx", "tc": "TC", "summary": "요약", "rules": ["../../unity/Assets/Sample/Rules"] }
```

- 통합 문서 하나에 TC 표와 요약 표가 탭으로 들어 있다. 다른 탭은 건드리지 않는다.
- 사람이 꾸민 것(굵은 글씨, 배경색, 칸 너비, 줄 바꿈, 틀 고정)은 그대로 남는다. 도구는 글자가 바뀐 칸만 고친다.
- 도구가 맨 뒤에 더한 칸은 꾸미지 않는다. 머리말과 칸 너비를 한 번 꾸며 두면 그 뒤로 남는다.
- 저장은 옆에 임시 파일(`qa.qaplay-tmp.xlsx`)을 다 쓴 뒤 바꿔치기한다. 도중에 멈춰도 원본이 반쯤 쓰인 채로 남지 않는다.
- 요약 표의 수(전체, 통과, 실패, 불안정)는 숫자로 적어서 Excel에서 바로 더하거나 그래프로 그릴 수 있다. 통과율은 `75%` 같은 글자다.
- 수식이 든 칸은 계산된 값으로 읽고, 수식은 저장한 뒤에도 남는다. 러너가 계산하지 못하는 함수는 `#NAME?`으로 읽힌다(Excel이 저장한 파일은 Excel이 계산해 둔 값을 읽으므로 해당하지 않는다).
- 차트, 피벗 테이블, 매크로가 든 통합 문서는 저장할 때 그 일부가 빠질 수 있다. TC 표는 그런 것이 없는 파일에 두고, 집계는 그 파일을 읽는 다른 파일에서 한다.

## 4. 규칙 상태와 "갱신 필요"

| 상태 | 뜻 |
|---|---|
| 있음 | 그 TC 번호가 적힌 규칙 파일이 있다 |
| 없음 | 규칙 파일이 없다. 규칙을 써야 하는 TC다 |
| 갱신 필요 | 규칙이 있는데, 규칙을 쓴 뒤에 시트의 내용이나 기대 결과가 바뀌었다 |

- 도구는 규칙이 있는 TC를 처음 볼 때 그때의 내용과 기대 결과를 "규칙 기준" 칸에 줄여 적어 둔다. 그 뒤로 둘 중 하나가 바뀌면 갱신 필요가 된다.
- 규칙을 바뀐 TC에 맞게 고친 뒤 `qaplay tc accept TC-012`를 실행하면 지금의 내용이 새 기준이 되고 있음으로 돌아간다.
- 규칙 상태는 `qaplay run`과 `qaplay tc sync`가 시트에 적는다.

## 5. 명령

| 명령 | 하는 일 |
|---|---|
| `qaplay tc list` | TC마다 규칙 상태, 최신 결과, 내용을 한 줄로 보여 준다. 시트에 쓰지 않는다 |
| `qaplay tc show TC-012` | TC 한 줄의 모든 칸과, 그 TC를 실행하는 규칙 파일을 보여 준다. 규칙을 쓰기 전에 읽는다 |
| `qaplay tc sync` | 모든 TC의 규칙 상태를 시트에 적는다 |
| `qaplay tc accept TC-012...` | 규칙을 바뀐 TC에 맞게 고쳤음을 알린다. 갱신 필요가 풀린다 |
| `qaplay run 규칙들` | 실행한 뒤 결과를 시트에 적는다(설정 파일이 있을 때) |

- `list`와 `show`에 `--json`을 붙이면 결과를 JSON으로 낸다.
- 규칙의 `tc`가 시트에 없는 번호이면 `run`이 알린다: `sheet: TC-999 is not in the sheet`
