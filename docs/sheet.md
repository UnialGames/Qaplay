# 시트 연동

기획자와 QA가 쓰는 TC 시트와 qaplay를 잇는 방법이다. 시트에는 "무엇을 확인할지"가 있고, 규칙 파일에는 "어떻게 확인할지"가 있다. 둘은 TC 번호로 이어진다.

- 상태: CSV 파일, Excel 파일(xlsx), Google Sheets를 지원한다. Google Sheets는 6절의 준비를 한 번 하면 된다
- 실행해 볼 수 있는 예: 저장소의 `samples/sheet/`(CSV: TC 표 `tc.csv`와 설정 `qaplay-sheet.json`), `samples/sheet-xlsx/`(Excel: 통합 문서 `qa.xlsx`와 설정)

## 1. 흐름

1. 사람이 시트에 TC 한 줄을 적는다(무엇을 확인할지)
2. 규칙을 쓰는 쪽(AI나 프로그래머)이 `qaplay tc show TC-012`로 그 줄을 읽는다
3. 규칙 파일을 쓰고 머리말에 `tc: TC-012`를 적는다([규칙 파일 명세](rules.md) 2절)
4. `qaplay run 규칙들`을 실행하면 러너가 그 TC의 줄에 결과를 적고, 요약 표에 한 줄을 더한다

같은 내용을 양쪽에 두지 않는다. 시트에는 실행 방법을 적지 않고, 규칙 파일에는 TC의 설명을 옮겨 적지 않는다.

## 2. 표 두 개

TC 표: TC 한 줄에 최신 결과만 있다. 실행할 때마다 줄이 늘지 않는다.

| 칸 | 누가 적나 | 내용 |
|---|---|---|
| TC 번호 | 사람 | 규칙 파일의 `tc`와 같은 글자 |
| 내용, 기대 결과 | 사람 | 무엇을 하고 무엇을 확인하는지. 이 둘이 바뀌면 규칙을 다시 봐야 한다(4절) |
| 그 밖의 칸(화면, 사전 조건, 우선순위, 담당 등) | 사람 | 도구는 읽기만 한다. 팀이 쓰던 칸을 그대로 둔다 |
| 규칙 상태 | 도구 | 있음 / 없음 / 갱신 필요 |
| 최신 결과 | 도구 | 통과 / 실패 / 불안정. 한 번도 돌리지 않았으면 비어 있다 |
| 최신 실행 | 도구 | 빌드 / 기기 / 일시 |
| 버그 리포트 | 도구 | 그 TC의 실패가 버그 리포트로 올라갔으면 그 번호(`BUG-0003`) |
| 리포트 | 도구 | 그 TC를 마지막으로 실행한 [실행 리포트](reports.md)의 ID. `qaplay reports show ID`로 본다 |
| 규칙 기준 | 도구 | 규칙을 쓸 때의 내용과 기대 결과를 줄인 값. 사람이 볼 필요는 없다 |

- 도구는 자기 칸만 고친다. 사람이 적은 칸은 건드리지 않는다.
- 도구의 칸이 시트에 없으면 맨 뒤에 더한다. 미리 원하는 자리에 그 이름의 칸을 만들어 두면 거기에 적는다.
- 같은 TC를 실행하는 규칙이 여럿이면 하나라도 실패하면 실패다.
- 이번에 실행하지 않은 TC의 결과는 그대로 둔다.
- 불안정은 처음에는 실패했다가 다시 돌려 통과한 것이다.

요약 표: 실행할 때마다 한 줄이 는다.

| 칸 | 내용 |
|---|---|
| 빌드, 실행 일시, 기기 | 무엇을 언제 어디서 돌렸는지 |
| 전체, 통과, 실패, 불안정 | 이번에 실행한 규칙의 수 |
| 통과율 | (통과 + 불안정) / 전체 |

## 3. 설정 파일

시트가 어디에 있고 칸 이름이 무엇인지를 `qaplay-sheet.json`에 적는다. 러너를 실행한 폴더에 이 파일이 있으면 따로 말하지 않아도 쓰고, 다른 곳에 있으면 `--sheet 파일`로 알려 준다. 안의 경로는 이 파일이 있는 폴더 기준이다.

```json
{
  "type": "csv",
  "tc": "tc.csv",
  "summary": "summary.csv",
  "rules": ["../../unity/Assets/Sample/Rules"],
  "columns": { "tc": "TC 번호", "content": "내용", "expected": "기대 결과", "rule": "규칙 상태", "result": "최신 결과" },
  "labels": { "passed": "통과", "failed": "실패", "flaky": "불안정", "notRun": "미실행", "ruleOk": "있음", "ruleMissing": "없음", "ruleOutdated": "갱신 필요" }
}
```

| 항목 | 뜻 |
|---|---|
| `type` | 시트의 종류. `csv`(기본), `xlsx`, `google` |
| `spreadsheet` | `google`일 때만: 시트의 주소(브라우저의 주소 칸에 있는 그대로) |
| `file` | `xlsx`일 때만: 통합 문서 파일 |
| `tc` | TC 표. `csv`에서는 파일, `xlsx`와 `google`에서는 탭 이름 |
| `summary` | 요약 표. `csv`에서는 파일, `xlsx`와 `google`에서는 탭 이름. 적지 않으면 요약을 남기지 않는다. 없으면 만든다 |
| `rules` | 규칙 파일이 있는 폴더들. 규칙 상태(있음, 없음)는 여기에서 `tc`가 적힌 규칙을 찾아 정한다 |
| `columns` | 칸 이름. 팀이 쓰던 시트의 이름에 맞춘다. 적지 않은 것은 아래의 기본 이름이다 |
| `labels` | 칸에 적는 말. 적지 않은 것은 아래의 기본 말이다 |

`columns`에 쓸 수 있는 이름과 기본값

| 이름 | 기본 칸 이름 | 표 |
|---|---|---|
| `tc`, `content`, `expected` | `TC`, `Steps`, `Expected` | TC 표, 사람이 적는 칸 |
| `rule`, `result`, `run`, `bugs`, `report`, `basis` | `Rule`, `Result`, `Last run`, `Bugs`, `Report`, `Rule basis` | TC 표, 도구가 채우는 칸 |
| `build`, `time`, `device`, `total`, `passed`, `failed`, `flaky`, `rate` | `Build`, `Time`, `Device`, `Total`, `Passed`, `Failed`, `Flaky`, `Pass rate` | 요약 표 |

`labels`에 쓸 수 있는 이름과 기본값: `passed`, `failed`, `flaky`, `notRun`(`not run`), `ruleOk`(`ok`), `ruleMissing`(`missing`), `ruleOutdated`(`outdated`)

- 모르는 이름을 적으면 실행하지 않고 알린다. 오타 난 설정이 조용히 무시되지 않는다.
- CSV 파일은 UTF-8이다. 쓸 때는 Excel이 한글을 제대로 읽도록 BOM을 붙인다.
- Excel로 열어 둔 파일(CSV, xlsx)에는 쓸 수 없다. 그때 러너는 결과를 적지 못했다고 알리고, 테스트의 종료 코드는 그대로 둔다. 읽기(`tc list`, `tc show`)는 열어 둔 채로도 된다.

Excel 파일(xlsx)일 때

```json
{ "type": "xlsx", "file": "qa.xlsx", "tc": "TC", "summary": "요약", "rules": ["../../unity/Assets/Sample/Rules"] }
```

- 통합 문서 하나에 TC 표와 요약 표가 탭으로 들어 있다. 다른 탭은 건드리지 않는다.
- 사람이 꾸민 것(굵은 글씨, 배경색, 칸 너비, 줄 바꿈, 틀 고정)은 그대로 남는다. 도구는 글자가 바뀐 칸만 고친다.
- 도구가 맨 뒤에 더한 칸은 꾸미지 않는다. 머리말과 칸 너비를 한 번 꾸며 두면 그 뒤로 남는다.
- 저장은 옆에 임시 파일(`qa.qaplay-tmp.xlsx`)을 다 쓴 뒤 바꿔치기한다. 도중에 멈춰도 원본이 반쯤 쓰인 채로 남지 않는다.
- 요약 표의 수(전체, 통과, 실패, 불안정)는 숫자로 적어서 Excel에서 바로 더하거나 그래프로 그릴 수 있다. 통과율은 `75%` 같은 글자다.
- 수식이 든 칸은 계산된 값으로 읽고, 수식은 저장한 뒤에도 남는다. 러너가 계산하지 못하는 함수는 `#NAME?`으로 읽힌다(Excel이 저장한 파일은 Excel이 계산해 둔 값을 읽으므로 해당하지 않는다).
- 차트, 피벗 테이블, 매크로가 든 통합 문서는 저장할 때 그 일부가 빠질 수 있다. TC 표는 그런 것이 없는 파일에 두고, 집계는 그 파일을 읽는 다른 파일에서 한다.

## 4. 규칙 상태와 "갱신 필요"

| 상태 | 뜻 |
|---|---|
| 있음 | 그 TC 번호가 적힌 규칙 파일이 있다 |
| 없음 | 규칙 파일이 없다. 규칙을 써야 하는 TC다 |
| 갱신 필요 | 규칙이 있는데, 규칙을 쓴 뒤에 시트의 내용이나 기대 결과가 바뀌었다 |

- 도구는 규칙이 있는 TC를 처음 볼 때 그때의 내용과 기대 결과를 "규칙 기준" 칸에 줄여 적어 둔다. 그 뒤로 둘 중 하나가 바뀌면 갱신 필요가 된다.
- 규칙을 바뀐 TC에 맞게 고친 뒤 `qaplay tc accept TC-012`를 실행하면 지금의 내용이 새 기준이 되고 있음으로 돌아간다.
- 규칙 상태는 `qaplay run`과 `qaplay tc sync`가 시트에 적는다.

## 5. 명령

| 명령 | 하는 일 |
|---|---|
| `qaplay tc list` | TC마다 규칙 상태, 최신 결과, 내용을 한 줄로 보여 준다. 시트에 쓰지 않는다 |
| `qaplay tc show TC-012` | TC 한 줄의 모든 칸과, 그 TC를 실행하는 규칙 파일을 보여 준다. 규칙을 쓰기 전에 읽는다 |
| `qaplay tc sync` | 모든 TC의 규칙 상태를 시트에 적는다 |
| `qaplay tc accept TC-012...` | 규칙을 바뀐 TC에 맞게 고쳤음을 알린다. 갱신 필요가 풀린다 |
| `qaplay run 규칙들` | 실행한 뒤 결과를 시트에 적는다(설정 파일이 있을 때) |

- `list`와 `show`에 `--json`을 붙이면 결과를 JSON으로 낸다.
- 규칙의 `tc`가 시트에 없는 번호이면 `run`이 알린다: `sheet: TC-999 is not in the sheet`

## 6. 시트 잇기 (Unity의 qaplay > Sheet)

어떤 시트를 쓸지는 팀이 고른다. Unity 에디터의 메뉴 **qaplay > Sheet**를 열어 종류를 고르고 위에서 아래로 따라가면 이어진다.

| 창의 단계 | 하는 일 |
|---|---|
| 시트의 종류 | Google Sheets, Excel 파일, CSV 파일 가운데 고른다 |
| 시트가 있는 곳 | 종류마다 다르다(아래 표). 다 넣고 "확인"을 누르면 시트를 열어 본다 |
| 탭과 칸 | 창이 찾아 낸 탭과 칸(TC 번호, 내용, 기대 결과)을 확인한다. 틀렸으면 목록에서 고친다. 비어 있으면 칸 이름을 적어 준다. "연결"을 누른다 |
| 이어진 시트의 TC | 이어지면 "TC 불러오기"로 시트의 TC가 보이고, "시트 열기"로 그 시트가 열린다 |

| 종류 | 시트가 있는 곳을 넣는 방법 |
|---|---|
| Google Sheets | 1. 키: 키를 받는 세 단계가 적혀 있고, 단계마다 그 Google Cloud 페이지를 여는 버튼이 있다. 내려받은 `.json` 파일을 "키 파일 고르기"로 고른다(그 PC에서 한 번). 2. 시트: 창이 보여 주는 주소(`...iam.gserviceaccount.com`)를 "복사"해 시트의 "공유"에 편집자로 더하고, 시트의 주소를 붙여 넣는다 |
| Excel 파일 | 팀이 쓰던 `.xlsx` 파일을 "고르기"로 고르거나 "새로 만들기"로 자리를 정한다. 새 파일은 연결할 때 칸 이름과 함께 만들어진다 |
| CSV 파일 | 팀이 쓰던 `.csv` 파일을 고르거나 새로 만든다. 요약은 그 옆의 `summary.csv`에 쌓인다 |

- 무엇이 잘못됐으면 창이 까닭과 할 일을 알려 준다: 키가 아닌 파일을 골랐다, 시트를 공유하지 않았다, 주소가 틀렸다, Sheets API를 켜지 않았다, 종류에 맞지 않는 파일이다.
- 설정 파일(`qaplay-sheet.json`)은 Unity 프로젝트의 맨 위 폴더에 생긴다. 그 폴더에서 `qaplay run`을 돌리면 결과가 시트에 적힌다. 비밀이 들어 있지 않으니 저장소에 넣는다.
- 종류를 바꾸고 싶으면 창에서 다른 종류를 골라 다시 "연결"한다. 잇는 데 실패하면 쓰던 설정이 그대로 남는다.
- 창은 러너(`qaplay`)를 불러서 일한다. 러너를 찾지 못하면 창이 그렇다고 알리고 고르게 한다. qaplay 저장소 안의 프로젝트라면 `dotnet build runner -c Release`로 빌드해 두면 저절로 찾는다.
- 창의 말은 PC의 언어가 한국어면 한국어, 아니면 영어다.

Unity 없이(빌드 서버 등) 준비하려면 `qaplay tc init`으로 같은 일을 한다. 종류부터 묻는다. 묻는 값은 옵션으로도 준다: `--type csv|xlsx|google`, `--file 파일`(csv, xlsx), `--spreadsheet 주소`(google), `--tab 탭 --lang ko --rules 폴더`.

### 종류를 더하려면

시트의 종류는 러너에서 하나의 전략(`ISheetProvider`)이다. 그 종류의 표를 읽고 쓰는 방법과, 처음 이을 때 무엇을 받는지를 안다. TC 표를 다루는 코드와 준비 명령은 종류를 모른다. 새 종류(Notion의 표 등)는 그 전략을 하나 만들어 `SheetProviders`에 넣으면 되고, Unity의 창에는 그 종류의 "어디에 있는지를 받는 부분"(`SheetKind`)을 하나 더한다.

## 7. Google Sheets의 준비

러너는 사람의 Google 계정으로 로그인하지 않고 키 파일로 로그인한다. Unity의 창이 안내하는 것과 같은 내용이다. 창을 쓰지 않을 때 본다.

### 준비 1: 키 파일 받기 (PC마다 한 번)

러너는 사람의 Google 계정으로 로그인하지 않는다. "서비스 계정"이라는 프로그램용 계정을 하나 만들고 그 계정의 키 파일로 로그인한다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)을 연다. 프로젝트가 없으면 하나 만든다(이름은 아무것이나).
2. 왼쪽 메뉴의 "API 및 서비스 > 라이브러리"(APIs & Services > Library)에서 "Google Sheets API"를 찾아 "사용"(Enable)을 누른다.
3. "IAM 및 관리자 > 서비스 계정"(IAM & Admin > Service Accounts)에서 "서비스 계정 만들기"를 누른다. 이름은 아무것이나 적고, 역할은 주지 않아도 된다.
4. 만든 계정을 눌러 "키"(Keys) 탭에서 "키 추가 > 새 키 만들기 > JSON"을 고른다. `.json` 파일이 내려받아진다. 이것이 키 파일이다.

- 키 파일은 비밀번호와 같다. 메일이나 메신저로 보내지 않고, 저장소에 넣지 않는다.
- 회사의 Google Workspace가 키 만들기를 막아 두었으면 4번에서 막힌다. 그때는 관리자에게 서비스 계정의 키를 요청한다.

### 준비 2: 설정 명령 실행 (Unity의 창을 쓰지 않을 때)

규칙을 돌리는 폴더(게임 저장소의 맨 위 등)에서 실행한다.

```
qaplay tc init
```

차례로 묻는다.

| 묻는 말 | 넣을 것 |
|---|---|
| `Path of the key file you downloaded (.json)` | 내려받은 키 파일의 경로. 탐색기에서 파일을 터미널로 끌어다 놓으면 경로가 들어간다 |
| `Address of the Google Sheet` | 시트를 브라우저로 열고 주소 칸의 주소를 그대로 붙여 넣는다 |
| `Which tab has the test cases` | 탭이 여럿일 때만 묻는다. 번호를 넣는다 |
| `Which column has the test case number` 등 | 칸 이름으로 알아내지 못했을 때만 묻는다. 번호를 넣는다 |
| `Language of the columns and words the tool writes: en or ko` | 빈 시트일 때만 묻는다. 한국어면 `ko` |
| `Folder with the rule files` | 규칙 파일의 폴더(예: `qa/rules`). 아직 없으면 그냥 Enter |

키 파일을 넣고 나면 명령이 주소 하나를 보여 준다.

```
The runner signs in to Google as: qa-runner@my-project.iam.gserviceaccount.com
Share your sheet with that address as an Editor (the Share button of the sheet), if you have not yet.
```

- 시트의 "공유" 버튼을 눌러 그 주소를 "편집자"로 더한다. 이것이 사람이 하는 두 번째 일이다.
- 공유를 잊고 시트 주소부터 넣어도 된다. 명령이 무엇을 하라고 알려 주고 기다린다. 공유한 뒤 Enter를 누르면 이어 간다.

명령이 하는 일

| 무엇 | 어떻게 |
|---|---|
| 키 보관 | 키 파일을 사용자 폴더의 `.qaplay` 폴더에 `google-key.json`이라는 이름으로 복사한다. 저장소 밖이다. 그 PC에서는 다시 묻지 않는다 |
| 접근 확인 | 시트를 열어 본다. 안 되면 까닭(공유하지 않음, 주소가 틀림, API를 켜지 않음)을 알려 준다 |
| 칸 찾기 | 첫 줄의 칸 이름에서 TC 번호, 내용, 기대 결과를 찾는다(`TC`, `TC 번호`, `ID`, `내용`, `Steps`, `기대 결과` 등). 시트가 비어 있으면 칸 이름을 적어 준다 |
| 설정 파일 | `qaplay-sheet.json`을 그 폴더에 쓴다. 비밀이 들어 있지 않으니 저장소에 넣는다 |
| 쓰기 확인 | 도구의 칸(규칙 상태 등)을 시트에 실제로 더해 본다 |

끝나면 `qaplay tc list`로 시트의 TC가 보이고, 그 폴더에서 돌리는 `qaplay run`이 결과를 시트에 적는다.

### 알아 둘 것

- 팀원의 PC마다 키가 필요하다. 설정 파일이 이미 저장소에 있으면 키만 두면 된다: 키 파일을 사용자 폴더의 `.qaplay/google-key.json`에 두거나, 환경 변수 `GOOGLE_APPLICATION_CREDENTIALS`에 키 파일의 경로를 적는다.
- 빌드 서버(CI)에서는 러너를 돌리는 계정의 사용자 폴더에 같은 식으로 키를 둔다. 워크플로에는 적을 것이 없다.
- 도구는 글자가 바뀐 칸만 고친다. 사람이 같은 시간에 다른 칸을 고치고 있어도 그 칸은 건드리지 않는다.
- 글자는 적은 그대로 들어간다. `=`로 시작하는 글자도 수식으로 풀리지 않는다. 요약 탭의 수는 수로 적혀 바로 더하거나 그래프로 그릴 수 있다.
- 시트의 서식(색, 굵기, 칸 너비, 필터, 조건부 서식)은 건드리지 않는다.
- 인터넷이 끊겼거나 Google이 거절하면 결과를 적지 못했다고 알리고, 테스트의 종료 코드는 그대로 둔다.
- 설정을 다시 하려면 `qaplay-sheet.json`을 지우고 `qaplay tc init`을 다시 실행한다. 묻는 값을 옵션으로 줄 수도 있다: `--credentials 파일 --spreadsheet 주소 --tab 탭 --lang ko --rules 폴더`.
