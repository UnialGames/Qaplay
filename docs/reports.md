# 실행 리포트

`qaplay run`을 한 번 돌릴 때마다 러너가 남기는 기록이다. 시트에는 TC마다 최신 결과만 있고, 실행 하나하나의 이력과 증거는 여기에 쌓인다.

- 상태: 러너가 폴더로 남기고, 명령으로 조회하고 정리하고, 브라우저로 본다(4절의 대시보드)
- 버그 리포트([버그 리포트](bugs.md))와는 다른 것이다. 실행 리포트는 "한 번 돌린 기록"이고, 버그 리포트는 "문제 하나의 보고와 추적"이다

## 1. 무엇이 남는가

실행한 폴더의 `qaplay-reports/` 아래에 실행 하나가 폴더 하나로 남는다. 폴더 이름이 그 실행의 ID다(시작한 시각).

```
qaplay-reports/
  20261128-164344/
    run.json                    요약: 빌드, 기기, OS, 걸린 시간, 규칙마다의 결과와 측정 수치
    02-leak-info.memory.csv     증거: 누수 검사가 되풀이마다 잰 메모리
    03-rapid-gift.png           증거: 실패한 그 화면
    03-rapid-gift.log           증거: 크래시나 프리징이 났을 때의 게임 로그
    game.log                    증거: 러너가 띄운 게임의 로그
    junit.xml                   --junit을 줬을 때 그 XML의 사본
```

| 남는 것 | 언제 | 종류 |
|---|---|---|
| 규칙마다의 결과(통과, 실패, 불안정), 실패한 시도의 내용, 걸린 시간, TC 번호, 버그 번호 | 항상 | 요약 |
| 측정 수치: 메모리 증가 추세, 프레임 시간, 기기 지표 | 그 검사를 한 규칙 | 요약 |
| 실패한 화면 | 규칙이 실패했을 때. 다시 돌려 통과해도(불안정) 실패했던 시도의 화면이 남는다 | `screenshot` |
| 크래시, 프리징 때의 게임 로그 | 러너가 게임을 띄웠고(`--app`, `--package`) 그 일이 났을 때 | `log` |
| 실행 전체의 게임 로그 | 러너가 게임을 띄웠을 때. 도중에 게임을 다시 띄웠으면 마지막에 띄운 것의 로그다 | `log` |
| 누수 검사의 메모리 기록 | `leakCheck`가 있는 규칙 | `data` |

- 증거 파일 이름 앞의 숫자는 그 실행에서 몇 번째 규칙인지다.
- 통과한 규칙의 화면은 찍지 않는다. 규칙마다 찍으면 실행이 느려지고 용량이 빠르게 는다.
- 크래시나 프리징으로 끝난 규칙은 화면이 없다(게임이 답하지 못한다). 그때는 로그가 증거다.
- 배치 모드로 띄운 게임은 화면을 그리지 않아 찍을 것이 없다.
- 리포트를 남기지 못해도(디스크 등) 테스트의 종료 코드는 바뀌지 않는다.
- `run.json`을 읽을 수 없는 폴더(쓰다가 멈춘 것 등)는 목록에 나오지 않고 정리에서도 건드리지 않는다. `qaplay reports list`가 그런 폴더가 있다고 알린다.
- `--reports 폴더`로 다른 곳에 남기고, `--reports off`로 남기지 않는다.
- `qaplay-reports/`는 저장소에 넣지 않는다(`.gitignore`에 적는다). QA PC나 빌드 서버에 쌓아 둔다.

시트를 쓰면 TC 표의 "리포트" 칸에 그 TC를 마지막으로 실행한 리포트의 ID가 들어간다([시트 연동](sheet.md)).

## 2. 보기

| 명령 | 하는 일 |
|---|---|
| `qaplay reports list` | 실행을 최근 것부터 한 줄씩: ID, 일시, 빌드, 기기, 통과와 실패 수 |
| `qaplay reports show ID` | 실행 하나: 규칙마다의 결과, 실패 내용, 측정 수치, 증거 파일의 경로. ID 자리에 `latest`를 쓰면 가장 최근 것이다 |
| `qaplay reports delete ID` | 실행 하나를 지운다 |

`list`, `show`, `expired`, `retention`에 `--json`을 붙이면 결과를 JSON으로 낸다. `show --json`은 `run.json`의 내용에 폴더 경로(`folder`)를 더한 것이다.

## 3. 보관 기한

용량 상한은 없다. 기한으로만 정리한다. 기한은 그 실행을 한 날부터 센다.

| 이름 | 무엇 | 기본 |
|---|---|---|
| `passed` | 통과한 규칙의 증거 | 14일 |
| `failed` | 실패했거나 불안정한 규칙의 증거 | 90일 |
| `summary` | 요약(`run.json`). 지나면 그 실행의 폴더가 통째로 지워진다 | 365일 |

- 실행 전체의 게임 로그(`game.log`)는 그 실행에 실패나 불안정이 하나라도 있으면 `failed`, 없으면 `passed`를 따른다.
- 증거가 하나라도 남아 있는 동안은 요약도 남는다.
- 중요 표시를 한 실행은 지워지지 않는다: `qaplay reports keep ID`. 푸는 것은 `unkeep`이다.

| 명령 | 하는 일 |
|---|---|
| `qaplay reports retention` | 지금의 기한을 보여 준다 |
| `qaplay reports retention failed=180 summary=forever` | 기한을 바꾼다. 값은 날 수나 `forever`(지우지 않음)다. 프로젝트 설정 파일(`qaplay.json`)의 `retention`에 들어간다 |
| `qaplay reports expired` | 지금 정리하면 무엇이 지워지는지 목록만 보여 준다 |
| `qaplay reports clean` | 기한이 지난 것을 지운다 |

`qaplay run`은 끝날 때마다 `clean`과 같은 정리를 한다. 지운 것이 있으면 한 줄로 알린다.

### 조건을 붙인 규칙

기한은 프로젝트 설정 파일(`qaplay.json`)의 `retention`에 있다. Unity의 **Project Settings > qaplay**의 "실행 리포트를 얼마나 둘지"에서 고치고, 조건을 붙인 규칙도 거기서 더한다. 파일에 직접 적어도 된다.

- 예전처럼 리포트 폴더에 `retention.json`이 있으면 러너는 정리하지 않고 알린다. 그 파일의 값을 모른 채 기본 기한으로 지우면 남기려던 증거가 사라지기 때문이다. 값을 설정으로 옮기고 그 파일을 지운다.

```json
"retention": {
  "summary": 365,
  "passed": 14,
  "failed": 90,
  "rules": [
    { "when": { "result": "failed", "kind": "screenshot" }, "days": 365 },
    { "when": { "build": "*rc*" }, "days": "forever" },
    { "when": { "tc": "TC-01*", "device": "Android*" }, "days": 180 }
  ]
}
```

| 조건 | 맞는 것 |
|---|---|
| `result` | `passed`, `failed`, `flaky`. 그 규칙의 결과다(요약과 실행 전체의 로그는 실행 전체의 결과) |
| `kind` | `screenshot`, `log`, `data`, 그리고 요약을 뜻하는 `summary`. 적지 않으면 요약을 포함해 모두에 맞는다 |
| `tc` | 그 규칙의 TC 번호 |
| `build` | 리포트의 빌드(`list`에 나오는 글자) |
| `device` | 리포트의 기기(`list`에 나오는 글자) |

- `tc`, `build`, `device`에는 `*`(아무 글자나)를 쓸 수 있다. 대소문자는 가리지 않는다.
- 한 규칙의 조건은 모두 맞아야 한다.
- 기본 기한과 맞는 규칙 가운데 가장 긴 기한을 쓴다. 규칙으로 기한을 줄일 수는 없다.
- 모르는 이름이나 조건을 적으면 실행하지 않고 알린다(종료 코드 2). 오타 난 조건이 조용히 무시되어 아무것도 지워지지 않는 일을 막는다.

## 4. 대시보드

리포트를 브라우저로 본다. QA PC에서 러너를 서버로 띄워 둔다. 따로 설치할 것은 없다.

```
qaplay dashboard
```

```
dashboard: http://localhost:27280/
showing the runs in C:\project\qaplay-reports
press Ctrl+C to stop
```

- `qaplay run`을 돌리는 폴더에서 띄운다(다른 곳의 리포트를 보려면 `--reports 폴더`). 띄워 둔 채로 다른 터미널에서 `run`을 돌리면 목록에 새 실행이 5초 안에 나타난다.
- 화면의 말은 브라우저의 언어를 따른다(한국어, 그 밖에는 영어). 밝은 화면과 어두운 화면도 브라우저의 설정을 따른다.

| 화면 | 보여 주는 것 |
|---|---|
| 실행 | 최근 실행마다 통과, 불안정, 실패한 규칙의 수(막대)와 목록. 막대나 줄을 누르면 그 실행이 열린다 |
| 실행 하나 | 빌드, 기기, 모델, OS, 걸린 시간. 규칙마다 결과, TC 번호, 버그 번호, 실패한 시도의 내용, 측정 수치, 증거(실패한 화면은 그림으로, 로그와 기록은 링크로). 기한이 지나 지워진 증거는 지워졌다고 나온다 |
| 추이 | 규칙이 잰 수치(프레임 시간의 평균과 느린 쪽 1%와 끊김 횟수, 메모리 증가 추세, CPU와 PSS와 배터리 온도)를 최근 50번의 실행에 걸쳐 선으로 보여 준다 |

- 추이는 같은 기기, 같은 규칙 파일, 같은 값끼리 한 줄이다. 기기가 다르면 프레임 시간이나 메모리를 견줄 수 없어서 섞지 않는다.
- 추이의 세로축은 0부터다. 값의 범위만큼만 잡으면 0.1ms의 흔들림이 큰 변화처럼 보인다. 정확한 값은 그래프 위에 마우스를 올리거나 카드의 "표"를 펴서 본다.
- 대시보드는 읽기만 한다. 중요 표시, 삭제는 `qaplay reports` 명령으로, 기한은 설정 화면에서 한다.
- Unity의 **Project Settings > qaplay**의 "대시보드 열기"가 대시보드를 띄우고 브라우저로 연다. 에디터를 닫으면 함께 멈춘다. 화면의 언어(`dashboard.lang`), 추이에 쓰는 최근 실행 수(`dashboard.trendRuns`), 추이로 그리는 측정값(`dashboard.metrics`), 포트(`dashboard.port`)도 거기서 정한다([프로젝트 설정](settings.md))

### 다른 PC에서 보기

기본으로는 띄운 PC에서만 열린다. 팀의 다른 PC에서도 보게 하려면 받을 주소를 함께 적는다.

```
qaplay dashboard --listen 0.0.0.0:27280
```

- 다른 PC에서는 `http://QA-PC의-이름:27280/`이나 `http://QA-PC의-IP:27280/`으로 연다.
- 처음 띄울 때 Windows 방화벽이 이 프로그램의 통신을 허용할지 물을 수 있다. 허용해야 다른 PC에서 열린다.
- 로그인이 없다. 그 PC에 닿을 수 있는 사람은 누구나 리포트(화면, 로그)를 볼 수 있다. 사내망에서만 쓴다. 인터넷에 내놓지 않는다.
- 주소 자리에 다른 이름(직접 붙인 도메인 등)을 써서 열면 거절한다. `localhost`, 그 PC의 이름, IP 주소로 연다.
- 포트를 바꾸려면 `--listen 8080`처럼 적는다.
